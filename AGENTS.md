# Project writing rules

- Never use em dashes (U+2014), en dashes (U+2013), or doubled hyphens as sentence punctuation in assistant messages or newly authored website copy, articles, metadata, and documentation.
- Use a period, comma, colon, semicolon, or parentheses instead. Use a plain hyphen for ranges and compound words.
- Preserve syntax-required characters in code, commands, URLs, and Markdown delimiters. Do not silently alter verbatim source evidence or byte-preserved legacy assets to enforce a prose preference.
- This is an explicit user preference, not a suggestion.
- In report-based articles, use at most one brief note explaining redaction and reconstructed code. Do not repeatedly interrupt the narrative with anonymization disclaimers. Keep necessary evidence limits precise and put publication status in private editorial metadata.
